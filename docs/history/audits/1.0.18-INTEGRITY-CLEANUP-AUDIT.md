# Mirage Projector 1.0.18 — Integrity Cleanup Audit

This audit was performed during the QA-driven 1.0.18 stabilization wave, before final packaging. Its purpose is to distinguish intentional compatibility identities from stale implementation names, remove superseded runtime code, and turn cross-system integrity assumptions into permanent regression gates.

## Compatibility identities intentionally retained

Two registry IDs predate the public terminology cleanup and **must not be renamed without an explicit registry remap/migration strategy**:

- `mirage_projector:arm_strap` — public name: **Shoulder Strap**.
- `mirage_projector:battery_pouch_expansion_patch` — public name: **Shoulder Strap Slot Expansion**.

Their model/texture/translation resource paths also remain keyed by those registry identities. Java symbols, upgrade-family identity and current user-facing prose use the new Shoulder Strap terminology.

## Deprecated API cleanup

The active source tree no longer uses the deprecated explicit `EventBusSubscriber.Bus` enum selector. Ordinary game-bus subscribers rely on the annotation default. Client MOD-bus handlers are registered from the dist-scoped `MirageProjectorClient` entrypoint through the injected mod event bus.

This preserves client-only classloading boundaries while avoiding the deprecated selector surface.

## Superseded code removed

The following runtime pieces had no remaining consumer after the 1.0.18 GUI/rearchitecture work and were deleted rather than left as misleading parallel implementations:

- `ShoulderDeviceScreen` — replaced by `PortableDeviceScreen`.
- `ShoulderDeviceControlPayload` — replaced by `PortableDeviceActionPayload`.
- `MirageLightProjectorRenderer` — obsolete renderer responsible for the old floating physical battery; the Light Projector now uses GUI state and dynamic-light submission without that renderer.
- `LightProfileMath` — unreferenced development-era light helper.
- the unused periodic `ClientHeldProjectors.updateLocalHud` loop and its cache state.

`ModNetworking` was cleaned at the same time so no removed payload remains registered.

## Naming/localization cleanup

Active Java uses `ShoulderStrapItem`, `ModItems.SHOULDER_STRAP`, `ModItems.SHOULDER_STRAP_SLOT_EXPANSION`, and `ShoulderUpgradeFamilies.SHOULDER_STRAP_SLOT_EXPANSION`.

Obsolete localization left behind by direct opposite-hand battery servicing, verbose debug tooltips, the superseded Shoulder Device screen and old Hand Projector tooltip instructions was removed from all three locales. Language-key parity remains mandatory.

War Banner configuration remains in `PortableDeviceScreen`; its presentation and facing buttons now display the currently selected state rather than only a generic action label.

## Cross-system integrity checks added

`tools/verify_1_0_18_integrity_cleanup.py` now verifies:

- stable legacy registry IDs versus current Java/public terminology;
- absence of deprecated explicit event-bus selectors;
- client MOD-bus registration through the dist-scoped entrypoint;
- absence of superseded classes/payload registrations;
- registration of every concrete `CustomPacketPayload` in the network package;
- existence of every mixin class declared by `mirage_projector.mixins.json`;
- language parity and removal of known dead keys;
- Portable Device GUI geometry after the War Banner/inventory overlap fix;
- removal of the persistent Hand Projector hotbar-refresh loop;
- absence of build/cache/binary residue in the source tree.

## Historical verifier policy

Historical 1.0.x gates continue to protect the gameplay/data contracts introduced by their versions, but they must accept intentional later replacements. For 1.0.18 this means, for example, validating `PortableDeviceActionPayload` instead of requiring the deleted `ShoulderDeviceControlPayload`, and validating GUI-only battery service instead of demanding the removed opposite-hand messages.

The historical registry IDs themselves remain protected and are **not** relaxed.

## Result

The cleanup is considered complete only when this integrity gate, the 1.0.18 stabilization gate, all still-relevant historical gates and the release auditors pass together on both the working tree and a clean extraction of the final source-only ZIP.
